검기형 보스 좌우 슬라이딩 16 / 벽 탈출 24 검증 보고 (2026-11-02)

브랜치: `feat/boss-sword2`. 작업 시작 당시의 미커밋·미추적 파일을 기준으로 비교했다. 원본 프로젝트를 Unity로 열거나 저장하지 않고, 현재 작업 파일을 기존 검증 복제 프로젝트에 복사해 Unity 6000.6.2f1 / D3D11에서 실행했다.

1. 기존 짧은 이동의 원인

   `ChooseRetreat`의 좌우 후보가 각각 `Random.Range(4f, 8f)`를 사용했다. 16유닛 후퇴는 별도 세 번째 후보여서, 설정의 `swordRetreatDistance = 16`이 좌우 재배치 후보에는 적용되지 않았다. 플레이어와 끝점이 가까우면 짧은 후보의 거리도 다시 조정했다. 따라서 단순한 속도 부족이나 시간 초과가 아니라, 짧은 목표 자체가 자주 선택되는 구조였다. 일반 후퇴에는 플레이어가 이동 반대편으로 넘어가면 조기 종료하는 조건도 있었다.

   수정 전 재실행에서 열린 공간의 짧은 후보는 103회, 실제 4.054~7.954유닛이었다. 60초 추격에서는 짧은 후보 25회, 평균 6.580유닛으로 기존 32회 이동 / 33회 공격을 재현했다.

2. 일반 이동 16유닛 적용

   실제 플레이어 `pierceDistance` 8유닛의 두 배를 모든 일반 좌우 후보의 예산으로 사용한다. 거리 난수와 별도의 장거리 세 번째 후보를 없애고, 좌우 두 후보가 각각 최대 16유닛을 요청한다. 방향은 기존 `SlideWeight`의 벽 여유·최근 방향 가중치와 플레이어 거리 가중치로 추첨한다. 최근 같은 방향 두 번 이후의 반복 제한도 유지한다.

   플레이어 반대쪽 이동은 `LongRetreat`, 플레이어 쪽 이동은 `Reposition`으로 구분한다. 끝점이 플레이어와 3유닛 미만으로 겹치는 후보는 제외하며, 이를 피하려고 열린 경로의 목표를 4~8유닛으로 줄이지 않는다. 플레이어 측면 변화만으로 실행 중 이동을 끊지 않고, 실제 지형·충돌·바닥·거리·시간 제한을 따른다.

   기존 `owner.Move(step)`를 프레임별로 사용한다. 새 텔레포트, 충돌 무시, 무적은 추가하지 않았다. 현재 보스 루트가 플레이어와 비고체인 기존 규칙은 그대로이며, 실제 고체 보스 충돌체를 추가한 검사에서는 플레이어를 통과하는 후보가 거절됐다.

3. 벽 탈출 24유닛 적용

   플레이어가 어느 편인지와 독립적으로 양쪽 실제 이동 가능 경로를 검사한다. 현재 설정에서는 한쪽 여유가 6유닛 미만일 때 경계 접근을 감지하고 그 방향을 후보에서 제외한다. 반대쪽 탈출 예산은 실제 대쉬 세 번, 즉 24유닛이다. BoxCast와 0.5유닛 간격 바닥 검사로 가능한 거리까지만 계획하고, 실행 중에도 매 프레임 검사한다.

   탈출 시작 후 5초 재사용 제한과 종료 후 3초 원래 벽 방향 복귀 제한을 유지한다. 실제 검증에서 일반 접근 이동이 복귀 제한을 우회하는 문제가 드러나, 같은 3초 제한을 접근 이동에도 적용했다. 양쪽이 막히거나 안전한 후보가 없으면 기본 공격 기회를 요청한다. 다음 슬라이딩에는 기존 공격 완료 조건이 필요하다.

4. 실제 일반 좌우 이동 측정

   고정 중앙 시작점에서 플레이어를 왼쪽·오른쪽에 각각 두고 80회씩, 총 160회 실제 이동 코드를 60Hz로 실행했다. 방향별 최소 30회 요구를 초과했다. 도달 판정 허용 오차는 0.01유닛이다.

   | 실제 방향 | 횟수 | 평균 / 최소 / 최대 실제 거리 | 준비 포함 시간 | 도달률 |
   |---|---:|---:|---:|---:|
   | 왼쪽 | 80 | 15.9997 / 15.9997 / 15.9997 | 0.533초 | 100% |
   | 오른쪽 | 80 | 15.9997 / 15.9997 / 15.9997 | 0.533초 | 100% |

   플레이어가 왼쪽인 80회에서도 좌 42 / 우 38, 플레이어가 오른쪽인 80회에서도 좌 38 / 우 42를 선택했다. 열린 경로에서 4~8유닛에 끝나는 사례는 0회였다.

5. 실제 벽 탈출 측정

   | 시작 벽 → 이동 방향 | 횟수 | 평균 실제 거리 | 준비 포함 시간 | 도달률 |
   |---|---:|---:|---:|---:|
   | 왼쪽 벽 → 오른쪽 | 30 | 23.9997 | 0.700초 | 100% |
   | 오른쪽 벽 → 왼쪽 | 30 | 23.9997 | 0.700초 | 100% |

   양쪽 장애물 제한 검사에서는 각각 12.591유닛에서 안전하게 정지했다. 양쪽 경로가 막힌 경우와 고체 플레이어 충돌 조건에서는 이동을 강행하지 않았다. 벽에서 4유닛 떨어진 위치에서도 반대 방향 탈출을 선택했다. 이미 선택한 일반 이동 경로에 새 장애물을 넣었을 때는 4.850유닛에서 정지했다. 탈출 직후 2초 동안 벽 쪽으로 돌아가는 프레임은 없었다. 이 짧은 실제 거리는 장애물 제한 검사의 결과이며 열린 공간의 일반 목표가 아니다.

6. 속도·시간 및 종료 조건

   | 항목 | 수정 전 | 수정 후 |
   |---|---:|---:|
   | 최고속도 / 상한 | 32 / 32 | 48 / 48 유닛/초 |
   | 슬라이딩 가속 | 240 | 420 유닛/초² |
   | 슬라이딩 감속 | 220 | 360 유닛/초² |
   | 준비 동작 | 0.045초 | 0.045초 |
   | 실제 16유닛 이동 | 0.717초 | 0.533초 |
   | 실제 벽 탈출 | 32유닛 / 1.217초 | 24유닛 / 0.700초 |

   저장된 `KarmaConfig.asset`의 검기형 `swordRetreatSpeed`도 48로 수정했다. 측정 최고속도는 부동소수점 오차를 포함해 약 48.0001유닛/초 이하, 60Hz 한 프레임 이동은 약 0.8유닛 이하이다.

   시간 예산은 기존의 준비 + 거리/최고속도 + 가속·감속 여유 + 0.12초 공식을 유지한다. 현재 일반·탈출 모두 최종 안전 타임아웃은 `pressureRetreatDuration`에 의해 1.05초이고, 실제로는 그보다 먼저 목표에 도달한다. 남은 거리 기반 감속, 장애물·바닥 제한, 피격에 따른 기존 강제 중단, 공격 전환 규칙을 유지했다. 0.6초의 오래된 `swordRetreatDuration` 값만으로 24유닛 이동을 자르지 않는다.

7. 청백색 잔상

   실제 외형의 Sprite/Transform 복제, 청백색 틴트, 좌우 반전, 수명 0.3초, 알파 0.58, 기존 머티리얼과 셰이더는 유지했다. 생성 설정 간격은 0.045→0.03초, 풀 상한은 7→8개로 조정했다. 60Hz에서는 약 0.033초마다 생성되고, 네 상황 모두 실제 최대 간격 1.600유닛, 활성 최대 8/8개였다. 이동 종료 후 생성 중지 및 자연 소멸, 정상 공격 재개를 검사했다.

8. 같은 60초 추격 조건 비교

   60Hz 게임 시간 60초, seed 6104, 기존 자동 추격 시나리오를 사용했다. 플레이어는 기존 `MoveSlash` 경로로 보행 보정 간격만큼 이동하고 보스에게 0.6초마다 소량 피해를 준다. 생존을 위한 기존 테스트 준비 무적은 이 비교에만 사용하며 게임 코드에 추가한 기능이 아니다. 공격 실행은 정상 Update와 코루틴을 따른다.

   | 측정값 | 수정 전 | 수정 후 |
   |---|---:|---:|
   | 완료 이동 총수 | 32 | 31 |
   | 좌 / 우 | 16 / 16 | 15 / 16 |
   | 일반 이동 횟수 | 짧은 25 + 긴 6 | 후퇴 16 + 재배치 15 |
   | 일반 이동 평균, 벽 탈출 제외 | 8.403유닛 | 15.9997유닛 |
   | 벽 탈출 횟수 / 평균 | 1 / 31.9998유닛 | 0 / 관측 없음 |
   | 당시 선택된 목표 도달 | 32/32 (100%) | 31/31 (100%) |
   | 일반 이동 중 16유닛 도달 | 6/31 | 31/31 |
   | 충돌·바닥으로 조기 중단 | 0 | 0 |
   | 시간 초과 | 0 | 0 |
   | 상태 전환 중단 | 0 | 0 |
   | 정상 공격 시작 | 33 | 32 |
   | 이동 실패, 실제 0.1유닛 미만 | 0 | 0 |
   | 60초 종료 시 진행 중 이동 | 1 | 0 |

   수정 후 이 추격 시나리오에는 벽 탈출이 발생하지 않았다. 따라서 추격 중 벽 탈출 평균을 24라고 채워 넣지 않았으며, 24유닛 실측은 5번의 별도 60회 검사에 근거한다. 이동과 공격 모두 한 회 감소했지만 공격은 32회 정상 수행됐다. 단일 시드의 자동 비교이며 모든 수동 전투 상황의 빈도를 보장하는 수치는 아니다.
