# 팀 최신 변경 병합 · 2026-10-31

개인 브랜치 `feat/minjae-boss-guard`에 팀 기준 `origin/feat/2d-prototype`의 `c605011`을 병합했다.
병합 전 방어형 코드·에셋·검사·문서는 `bfbdced` 커밋으로 보존했다. 다른 작업 브랜치를 수정하거나 원격 저장소에 푸시하지 않았다.

## 함께 반영한 팀 변경

- `SwordWave`, `RisingSlash`, `Guard`로 기술 이름을 정리했다. 저장된 기술 번호는 그대로다.
- 플레이어 웅크리기와 테스트용 무적 전환, 피격·사망 표시를 반영했다.
- 보스 쓰러짐 → 선택 → 고유화 → 계승·부활 흐름과 계승형 전투 자세를 반영했다.
- 팀의 이미지 폴더 정리를 반영하고 방어형 전용 이미지 17개를 목록에 추가했다. 현재 게임 이미지 47개를 관리한다.

## 유지한 방어형 규칙

- GD01은 스테이지 시작부터 존재한다. 회피나 일반 후딜레이로 사라지지 않으며 GD02 내려베기 패링 또는 GD05 성공으로 해제된다.
- GD02는 모든 방어형 형태에서 0.5초 빛과 패링 입력을 연결한다. 충격파는 검기 계승과 체력 50% 이하를 함께 만족할 때만 나온다.
- GD03은 큰 방패 도착 → 분열 → 순차 추적으로 이어진다. 추적 속도 30, 거리별 추적 시간, 복귀 0.4초와 복귀 시 피해만 주는 규칙을 유지한다.
- GD04는 벽까지의 공간에 맞춰 플레이어 방향으로 계단을 생성한다. 방어막이 있는 상태에서 뒤로 넘어가면 GD02로 연계한다.
- GD05는 패턴 중 무적, 확대된 돔·공격을 유지한다. 성공하면 방어막을 해제하고 강화 상태에서도 4초의 공격 기회를 준다. 실패하면 방어막이 남는다.
- GD02·GD03·경직 전용 PNG 및 스프라이트 메타데이터는 병합 전 에셋을 유지했다.

## 해결한 충돌

기존의 계승 외형 고정 처리가 팀의 새 피격 자세를 덮고 있었다. 완성된 계승 시트가 있으면 그 시트의 자세를 사용하고, GD02와 패링 경직에서는 전용 자세를 우선 표시한다. 스테이지 장비·방향·크기와 발 위치를 검사했다.

GD02 가져오기 보조 도구가 삭제된 예전 함수를 호출하던 컴파일 오류를 수정했다. 기존 Sprite ID를 유지하는 Unity 가져오기 API를 사용한다. 전체 시트 재가져오기에서도 GD03의 별도 방패·파편 연결을 보존한다.

팀에서 제거한 예전 자동 생성 이미지가 로컬에 남아 있어 `output/merge-backup/retired-generated-art/`로 옮겨 보관했다. 현재 에셋과 혼동되지 않으며 원본은 삭제하지 않았다.

## 검증

- Unity 6000.6.2f1 컴파일 통과.
- 핵심 규칙: 398개 통과.
- GD01–GD05 실제 실행: 245개 통과.
- 팀 전체 패턴 21회와 웅크리기·무적·사망·계승 흐름: 2,483개 통과.
- GD02: 208개 통과.
- GD05 성공·실패 보상과 GD01 재생성: 28개 통과.
- 경직: 176개 통과. 계승 경로 5가지 × 양방향, 실제 게임 화면 30장.
- Unity 에셋 연결: 이미지 47개와 이름으로 선택하는 포즈 361개 통과.
- `tools/validate-complete-art.py`: 이미지 목록·원본 파일·가져오기 정의 일치.

실행 검사는 관찰을 위해 복제한 설정에서 플레이어 체력을 높인 경우가 있다. 실제 플레이어가 모든 공격을 회피해 완주했다는 의미는 아니다. 검사 후 원래 설정을 복원했다.

기존 동선·연출 검토 항목은 `GUARD_RELATIONSHIP_REVIEW.md`에 남아 있다. 이번 병합을 이유로 기획을 추가 변경하지 않았다. Unity 편집 도구의 한글 경로 관련 임시 어셈블리 오류는 실행 세션을 새로 시작해 처리했으며, Console 전체에 과거 오류가 없다는 뜻은 아니다.

병합 전 생성한 PDF는 당시 코드의 기록이다. 이번 병합에서 기술 식별자와 파일 이름이 바뀌었으므로 현재 코드를 확인할 때는 이 브랜치의 원본과 `BOSS_PATTERNS.md`를 기준으로 한다.
