# 검기형 보스 랜덤 슬라이딩 / SW04 두 번째 패링 검증

브랜치: `feat/boss-sword2`. 이번 요청 시작 시점의 미커밋·미추적 파일 665개를 해시로 기록하고 작업했다. 아래 비교의 ‘수정 전’은 이번 요청 직전의 16유닛 일반 후퇴·16유닛 벽 탈출 구현이다.

1. **한 방향으로 벽까지 물러나던 원인**

   기존 일반 후퇴 후보는 플레이어와 멀어지는 방향 하나뿐이었다. 최근 방향을 기억해도 반대 방향의 짧은 재배치 후보가 없어 이동을 보류하거나 같은 쪽으로 다시 후퇴했다. 플레이어가 계속 왼쪽에서 추격하면 오른쪽 16유닛 이동을 반복하다 벽 탈출 조건에 들어갔다. 벽 탈출은 이미 있었지만 벽에 도달하기 전 위치를 바꾸는 선택지가 부족했다.

2. **새 방향 선택 알고리즘**

   `ShortReposition`, `LongRetreat`, `WallEscape`를 구분했다. 좌우 짧은 이동 후보 두 개와 플레이어 반대쪽 장거리 후보를 실제 공간 검사 후 가중치로 선택한다. 짧은 이동은 4~8유닛이며, 끝점이 플레이어와 겹치지 않도록 최소 간격을 확보한다. 끝점의 벽 여유가 줄면 가중치를 낮추고, 최근 8초 내 같은 방향은 가중치 0.25배, 세 번째 연속 선택은 제외한다. 가까운 압박에서는 거리를 벌리는 쪽에 우선권을 준다. 중거리의 짧은 재배치 기회는 35%이며 보류 시 0.6초 뒤 재평가한다.

   기존 공격 완료 토큰과 실효 후퇴 쿨다운 **1.2초**, 이동 후 공격 기회 **0.65초**를 유지했다. 패턴 실행 중 이동으로 끊지 않는다. 이동 종료 시 기본 공격을 요청하고 다음 이동은 공격 완료 후 가능하다. 벽 탈출은 시작 후 5초 재선택 제한, 종료 후 원래 벽 방향으로 3초 재이동 제한을 유지한다.

   지형 BoxCast, 실제 이동 여유, 0.5유닛 간격 바닥 검사, 끝점 및 매 프레임 검사를 모든 후보에 적용한다. 현재 보스 루트는 물리 Collider2D가 없는 기존 규칙을 사용하므로 재배치는 플레이어 쪽으로 지나갈 수 있다. 충돌 무시나 무적을 추가하지 않았다. 고체 보스 충돌체를 추가한 검사에서는 플레이어 충돌을 존중해 통과를 거부한다.

3. **실제 이동거리와 대쉬 기준**

   플레이어 방향 대쉬의 `pierceDistance`는 **8유닛**이다. `BeginDirectionalSlash → MoveSlash`로 이동을 한 번 실행하며 `Pierce` 포즈 0.22초는 이동 지속시간이 아니다. 속도×지속시간으로 8유닛을 계산하지 않았다. 벽과 경기장 경계에서는 실제 경로가 잘린다. 플레이어 코드·설정은 이번에 변경하지 않았다.

   중앙 독립 표본의 짧은 이동은 **4.054~7.954유닛, 평균 6.698유닛**이었다. 일반 후퇴는 **15.99984유닛**, 벽 탈출은 **31.99984유닛**이었다. 현재 일반 후퇴는 `max(기존 유효 예산, 실제 대쉬 설정×2)`, 벽 탈출은 그 두 배이면서 최소 대쉬×4로 계산한다. 현재 설정에서 각각 16·32유닛이며, 32유닛 예산은 벽 탈출 분기에서만 사용한다.

4. **좌우 선택 횟수와 기존 대비**

   중앙에서 보스 위치와 플레이어 측면을 고정하고 각각 60회 선택 기회를 줬다. 실제 런타임 이동 코드와 Physics2D를 60Hz로 실행했다. 각 이동 뒤 공격 완료 토큰을 제공한 독립 표본 검사이며, 아래 보류는 이동 실패와 구분한다.

   | 플레이어 측면 | 수정 전 좌/우 | 수정 전 보류 | 수정 후 좌/우 | 짧은/일반 | 연속 같은 방향 최대 |
   |---|---:|---:|---:|---:|---:|
   | 왼쪽 | 0 / 36 | 24 | 26 / 34 | 39 / 21 | 2 |
   | 오른쪽 | 37 / 0 | 23 | 33 / 27 | 39 / 21 | 2 |

   두 경우 모두 수정 후 이동 실패는 0회였다. 별도의 정상 AI 60초 추격 비교는 다음과 같다. 이 검사는 실제 씬의 정상 Update·코루틴을 사용하며, 자동 추격자가 플레이어의 기존 `MoveSlash` 경로로 작은 보행 간격만큼 이동하고 0.6초마다 보스에게 일반 피해를 준다. 생존을 위한 테스트용 초기 무적은 이 이동 비교에만 사용한다. SW04 실제 피격 검사는 아래와 같이 별도 구성했다.

   | 60초 추격, seed 6104 | 수정 전 | 수정 후 |
   |---|---:|---:|
   | 완료 이동 총수 | 17 | 32 |
   | 좌 / 우 | 8 / 9 | 16 / 16 |
   | 짧은 / 일반 / 벽 탈출 | 0 / 9 / 8 | 25 / 6 / 1 |
   | 전체 이동 평균 실제 거리 | 16.000 | 9.140 |
   | 짧은 이동 평균 실제 거리 | 해당 없음 | 6.580 |
   | 일반 / 벽 탈출 평균 실제 거리 | 16.000 / 16.000 | 16.000 / 32.000 |
   | 같은 방향 연속 선택 최대 | 2 | 2 |
   | 이동 실패 | 0 | 0 |
   | 정상 AI 공격 시작 | 34 | 33 |

   짧은 이동이 추가됐으므로 전체 평균은 낮아졌다. 일반 후퇴 16유닛은 유지하면서 벽까지 밀리는 횟수를 줄였고 공격 기회도 유지했다. 단일 시드의 자동 추격 비교이며 사람의 실전 밸런스 평가를 대신하지 않는다.

5. **32유닛 벽 탈출과 잔상**

   왼쪽 벽에서 오른쪽 60회, 오른쪽 벽에서 왼쪽 60회 모두 실제 **31.99984유닛**을 연속 이동했다. 매 표본을 같은 벽 시작점으로 재배치한 독립 검사이므로 벽 표본의 같은 방향 60회는 실전 연속 후퇴를 의미하지 않는다. 벽 탈출 외 일반 이동의 예산은 32로 늘리지 않았다.

   양쪽 장애물 제한 검사에서는 각각 **12.593유닛**만 이동하고 안전하게 멈췄다. 반대 경로가 완전히 막혔거나 실제 고체 보스 충돌체로 플레이어가 막는 경우에는 탈출을 거부했다. 새 플레이어 무적 없음, 속도 상한, 연속 이동, 탈출 후 2초간 원래 벽으로 되돌아가는 이동 없음도 검사했다. 별도의 정상 Update 검사에서는 양쪽 탈출 후 정상 공격이 다시 시작됐다.

   기존 속도 상한 32유닛/초, 가속 240·감속 220, 준비 0.045초를 유지하고 거리에 맞는 시간 예산을 사용한다. 기존 청백색 잔상은 0.045초 간격·0.3초 수명·풀 7개를 유지한다. 짧은 재배치와 긴 탈출 모두 기존 재배치 잔상 모드로 지나온 실제 외형과 좌우 반전을 기록한다. 잔상 아트·shader·소스는 이번에 변경하지 않았다.

6. **첫 검기를 맞은 뒤 두 번째 패링 가능 여부**

   **가능하다.** 실제 비행하는 첫 검기로 체력이 감소한 뒤 실제 Input System 키보드의 **K 입력**을 게임의 입력 액션에 전달했다. `TryCounter → BeginCounter → TryAttackHit → TakeDamage → ConsumeCounter → ParryCount 증가` 경로를 사용했다. 첫 피격 후 무적·경직·쿨다운을 초기화하지 않았고 탄속·발사 간격·투사체 위치를 조작하지 않았다. 테스트 준비 단계에서만 기존 공용 테스트의 200초 무적을 제거했다.

7. **두 번째 검기 실제 성공 판정**

   B의 정상 피격 후 두 번째 패링에서 `ParryCount`가 **0→1**로 증가하고 `Result=ParrySuccess`, `Result=ParryDelivered`가 기록됐다. K 포즈나 입력 시도만 보고 성공으로 간주하지 않았다. K가 실제 `KarmaInput.Pressed(Counter)`에 도달했는지와 카운터 준비 상태도 기록했다.

8. **성공 후 3·4번 처리와 A~F 결과**

   | 사례 | 실제 입력·피격 조건 | 실제 패링 | 후속 취소 |
   |---|---|---|---|
   | A | 첫 검기에 K | 1번 성공 | 2·3·4번 |
   | B | 첫 검기에 실제 피격 후 K | 2번 성공 | 3·4번 |
   | C | 첫 검기 점프 회피 후 K | 2번 성공 | 3·4번 |
   | D | 앞선 검기를 허용하고 K | 3번 성공 | 4번 |
   | E | 앞선 검기를 허용하고 K | 4번 성공 | 추가 대상 없음 |
   | F | K 창을 일찍 열어 만료 | 성공 없음 | 없음, 네 발 발사 유지 |

   C에서는 첫 점프를 추적한 두 번째 검기의 고정 경로에 두 번째 정상 점프로 접근한 뒤 K를 입력했다. 성공 프레임에 후속 접촉 기록 소비, 슬롯의 충돌·경고·이펙트 비활성화를 함께 검사하고 즉시 캡처했다. 별도로 네 발이 이미 비행 중인 제어 회귀 검사에서 두 번째 패링 후 후속 탄 비활성화, 앞선 탄·다른 공격 보존, 같은 프레임 추가 피해 불가를 검사한다. 이 제어 회귀 검사는 탄을 고정하는 기존 보조 검사이며, 실제 B 재현 결과를 대신하지 않는다.

9. **성공처럼 보였으나 실패하는 정확한 조건**

   - **피격 무적 중 접촉:** 첫 피격 후 계속 보스 쪽으로 걸으면 두 번째 도착이 빨라진다. 정상 정지 사례의 피격 간격은 **0.8500초**, 접근 사례는 **0.6167초**였다. 접근 사례는 접촉 시 **0.0833초**의 피격 무적이 남았다. K가 수락되어 `CounterReady=True`여도 접촉 시 0.7초 피격 무적이 남으면 `TakeDamage`가 `ConsumeCounter` 이전에 반환한다. 결과는 `IgnoredInvulnerability`, `ParryCount=0`이며 3·4번을 취소하지 않는 것이 기존 규칙이다. 접촉 기록은 이미 소비되어 무적 종료 뒤 같은 검기로 다시 패링하지 않는다.
   - **앞선 K 시도의 쿨다운:** 첫 검기에서 K를 너무 일찍 써 0.18초 창이 만료되면 피격된다. 두 번째 K 때 1.1초 공용 Guard 능력 쿨다운이 약 **0.117초** 남는 사례를 재현했다. K 액션은 관측됐지만 `TryCounter`가 거부하고 `CounterReady=False`, 두 번째는 실제 피해가 됐다. Guard 능력과 공유하는 쿨다운도 고려해야 한다.
   - 위 사례의 실제 플레이어 `Stunned`는 **False**였다. SW04의 일반 피격 Hurt 표시는 입력을 막는 강제 스턴과 다르다. 이번 재현에서 일반 피격 경직이나 입력 누락이 원인은 아니었다.

   따라서 재현된 증상은 **A(패링 성공 판정이 발생하지 않음)**에 해당한다. 성공이 전달됐는데 후속 취소가 누락되는 **B는 재현되지 않았다**. 전체 플레이어 패링 시스템은 변경하지 않았다. 향후 피격 직후에도 반드시 다음 검기를 패링할 수 있는 설계를 원하면, SW04의 실제 도착 간격 보장이나 ‘준비 포즈/성공 피드백’ 구분을 별도 설계할 수 있다. 이번에는 네 발 구조·기존 발사 시간·무적·입력 창·쿨다운을 유지했다.

10. **SW04 수정 전후 동작 및 진단 옵션**

    수정 전·후 동일한 실제 K 입력 A~F 및 두 실패 조건에서 결과가 같았다. 기존 순번·접촉 기록·묶음 ID 기반 취소 로직을 유지하고 진단만 추가했다. `sw04DebugLogging`은 기본 false이며 Editor/development 실행에서만 로그를 출력한다. `Released`, `PlayerHit`, `IgnoredInvulnerability`, `ParrySuccess`, `ParryDelivered`, `Cancelled`의 비행/예약 상태와 남은 미소비 활성 탄 수를 기록한다. 플레이어의 private 상태는 진단 옵션을 켰을 때 읽기만 한다.

    묶음별 네 접촉 기록과 허용 마지막 순번을 유지한다. 실제 패링 순번 N보다 뒤의 동일 묶음만 즉시 비활성화하고, 발사 예약도 취소한다. 이미 앞서 나온 탄은 소급 제거하지 않는다. 재사용 시 새 묶음 ID·네 접촉 기록을 만들며 이전 묶음 이벤트를 무시하는 회귀 검사도 포함한다.
