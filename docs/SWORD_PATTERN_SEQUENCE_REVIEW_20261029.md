### SW04: 회전 장식 4개와 반격 1발이 별도 구현

기존 `CounterWard()`는 무피해 `GuardianVFX/Blade` 장식 4개를 만들었지만, 피격 반응에서는 보스 중심에서 `Attack()`을 한 번만 호출했다. 장식 검을 실제 공격으로 소비하는 연결이 없었다. 이번 시작 코드에 4발 동시 사출 구현은 없었다.

현재는 회전 검에도 기존 `SW04_CounterWave` PNG와 기존 공격 크기를 적용한다. 하나의 피격 트리거에서 다음 단계를 정확히 네 번 실행한다.

1. 선택한 회전 검은 자신의 위치에서 플레이어의 실제 Collider 중심을 0.35초 추적한다. 파란 전조를 매 프레임 갱신한다.
2. 사출 위치와 방향을 고정하고 기존 `counterWarning` 기본값인 0.45초 동안 주황 전조를 표시한다.
3. 해당 회전 이미지를 즉시 비활성화하고 같은 위치·방향에서 독립 투사체 1개를 생성한다.
4. 마지막 검을 제외하고 0.16초를 기다린 후 다음 검이 플레이어의 새 위치를 조준한다.

프레임 반올림 전 첫 조준 시작을 0으로 잡은 발사 예정 시각은 **0.80 / 1.76 / 2.72 / 3.68초**, 발사 간격은 **0.96초**다. 일반·강화 모두 같은 반응 시간을 사용한다. 실제 실행은 프레임 경계에 맞춰 늦어질 수 있으며 아래 실측을 기준으로 한다.

`wardResponseRunning`은 실행 중 추가 피격이 새로운 4발을 예약하지 못하게 한다. 회전 검 수는 **4→3→2→1→0**으로 줄어든다. 회전 위치는 검기의 기존 크기를 고려해 지면과 좌우 벽 안으로 보정한다. 기존 지면 아래 회전 위치를 그대로 투사체 원점으로 쓰면 수명이 즉시 끝나는 문제가 있어 필요한 보정이다.

### 검막 만료와 회복

기존 검막은 활성화 후 3초가 끝나면 반격 경고와 잔여 투사체를 함께 취소했다. 만료 직전 시작한 반격은 첫 발도 나오지 않을 수 있었다.

현재 피해 감소는 **기존 3초 마감 시각**에 해제된다. 이미 시작된 네 발은 그 뒤 무방어 상태로 계속 실행한다. 네 번째 사출 직후 검막·전조를 정리하고 회복 상태에 들어간다. 원래 회복 최소 시간 **일반 1.008초 / 강화 0.82656초**를 유지하되, 발사된 검기가 아직 살아 있으면 그 수명이 끝날 때까지 무방어 회복 상태를 유지한다. 네 번째 검기를 회복 진입과 동시에 삭제하지 않기 위한 처리다. 따라서 실제 회복과 전체 패턴 시간은 기존보다 길어질 수 있다.

무피격일 때는 기존 3초 검막 후 원래 회복을 사용한다. 그 경우 프레임 반올림 전 전체 시간은 일반 **4.638초**, 강화 **4.34316초**로 유지된다. 사망·기절·패턴 중단·재시작은 남은 사출, 전조와 이미 발사된 검기를 즉시 정리한다.

### SW03: 경기장 대신 앞선 검기의 짧은 이동 구간 사용

기존 코드는 선행 검기의 시작점과 끝점으로 검흔 배치 구간을 제한했다. 그 구간이 짧거나 플레이어와 안전 공간의 거리가 길면 `pair=false`가 되어, 경기장에 충분한 공간이 있어도 검흔 하나만 생성했다. 좌우 가장자리에서 비대칭으로 보일 수 있는 원인이다.

이제 경기장 전체 `[-15, 55]` 안으로 **쌍 전체를 이동**한다. 실제 두 피해 경계 사이 간격은 표준 Collider에서 **3.0**, 너비 2.6 검사에서는 **3.1**이다. 검흔 크기 **4.5×13.5**, 상승 **0.25초**, 상승 후 유지 **3초**, 실제 공격 수명 **3.25초**, 전조와 피해량은 유지한다. 두 검흔과 안전 간격을 수용할 물리적 폭이 부족할 때만 하나로 대체한다.

### SW05: 수량 설정과 이미 움직이는 검기의 경로 평가

기존 7회 사출 구조와 경계 도달 수명은 유지한다. 과거 4~8발 설정은 직렬화 보존용으로 남기고, 새 `aerialSwordVolleyMin/Max`를 **15/15**로 사용한다. 기본 총량은 **7×15=105발**이며, 향후 12~18 등 별도 범위로 조정할 수 있다. 기존 Config asset을 다시 저장하지 않았다.

밀도를 올린 검사에서 `int.MaxValue` 시드의 두 번째 묶음이 경로 검사를 통과하지 못했다. 이미 위치가 확정된 검기에 새 발사의 시간 오차를 다시 적용해 안전 후보를 과도하게 배제하는 부분을 확인했다. `SafeFromLive()`는 실제 현재 위치부터 원래 크기의 연속 회전 박스와 기존 플레이어 여유 0.15로 검사한다. 새로 예고하는 검기의 발사 시점 오차 여유는 유지한다. 실제 피해 박스는 줄이지 않았다. 시드 목록을 제거하거나 회피 검사를 생략하지 않았다.

실행: `output/validation/sw03-sw04-sw05-20261029/performance-20261029-050539/`의 `sword-performance.json`. 실제 게임 카메라가 있는 Play Mode에서 여섯 번 실행했다. 첫 두 비교군은 **현재 코드에서 과거 수량 설정 4~8을 메모리로만 재현**한 것이다. 과거 PASS나 과거 실행 시간을 재사용한 값이 아니며, 변경 전 전체 소스를 실행한 것과는 구분한다. Config asset은 저장하지 않았다. 시드는 모두 20261029다.

일반 비교군에서 전체/방어 시간이 각각 약 0.033초 짧아진 것은 고정된 체공 시간을 줄인 결과가 아니다. 마지막 검기의 실제 경계 도달과 프레임 반올림에 따라 종료하던 기존 정책을 유지한다. 사출 간격, 준비 0.8초, 상승·착지 각 0.5초, 최소 회복 일반 1.44초/강화 1.1808초는 그대로다. 수량이 늘어도 동시에 활성인 실제 투사체는 이번 시드에서 **10→19**, 전조는 **8→15**, 직계 소유 객체는 **21→최대 38**이었다. 105개 전부를 패턴 끝까지 보관하지 않는다.

위 수치는 검사 드라이버와 Editor의 비용을 포함하며 GPU 프레임 시간 자체는 아니다. 여섯 실행의 수량·수명·정리는 PASS지만, 큰 최대 프레임 지연이 있으므로 이를 **30/60FPS 완전 안정성 PASS로 해석하지 않는다**. 큰 지연은 GC 수집 0회인 비교군 및 새 패턴에서도 관찰했다. 진단용 검사로 지연 시점을 추가 기록했으며, 해당 결과를 아래에 구분해 남긴다. 근거 없이 공격 판정을 줄이거나 전역 풀링을 도입하지 않았다.

추가 진단 실행: `output/validation/sw03-sw04-sw05-20261029/performance-20261029-050944/`. 저장소의 소스는 바꾸지 않고 격리 프로젝트 검사 파일에만 느린 프레임 로그를 추가했다. 진단 파일은 `performance-diagnostic-fixture.cs`에 남겼고 실행 후 격리 검사도 원본과 같은 해시로 되돌렸다.

- 과거 수량 비교군 첫 형성 부근에서도 **100.11ms**, GC 수집 **0회**가 나왔다.
- 새 15발 일반 60Hz 첫 형성 부근은 **20.73ms**, 프레임 GC 할당 **34,858B**, 수집 **0회**였다.
- 새 15발 강화 30Hz의 최대 **48.55ms**는 패턴 시작 **0.0667초**, **아직 공중 방어·검기 형성 전인 Telegraph**에서 나왔다. 이때 할당은 **2,504B**, 수집 **0회**였다.
- 새 15발 강화 60Hz 최대는 재실행에서 **14.51ms**였다. 여섯 번 모두 발수·시간·정리는 다시 PASS였다.

따라서 큰 지연 전체를 105발 동시 생성이나 GC 때문이라고 확정할 수 없다. 강화 시작 시 기존 연출/Editor 준비 비용도 후보이지만 이 로그만으로 단일 호출을 원인으로 확정하지 않는다. 활성 19발·전조 15개·최대 직계 객체 38개이며 수집과 최대 지연의 대응도 일정하지 않아, 투사체 접촉 초기화까지 바꾸는 풀링을 이번 최소 수정에 추가하지 않았다. **지속적인 60FPS 안정성은 아직 보증하지 않는다.** 다음 실제 Player 프로파일에서는 첫 검기 형성과 강화 진입을 따로 캡처하고, 생성 비용이 병목으로 확인되면 SW05의 무피해 전조/형성 객체부터 재사용하는 범위가 적절하다.

## 실제 플레이에서 볼 항목

자동 경로 검사는 가능한 이동·점프 경로가 있음을 확인한다. 사람이 전조를 처음 보고 선택하는 난이도까지 보장하지는 않는다. 특히 벽 근처에서 다음 검기의 파란 추적과 이전 검기의 주황 고정을 읽을 수 있는지, 네 번째 사출 후 무방어 회복과 남은 검기가 자연스럽게 보이는지 확인한다. 15개 전조의 겹침과 원거리 칼날 대비는 실제 Game View 해상도에서도 확인한다. 성능 측정은 Editor와 검사 드라이버의 비용을 포함하므로 최종 Windows Player에서 프레임 시간과 GC를 다시 확인한다.
