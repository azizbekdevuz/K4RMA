# 검기형 보스 벽 탈출 / SW03 5차례 / SW04 패링 연쇄 취소

`feat/boss-sword2`에서 완료했다. 작업 시작 시점의 기존 미커밋·미추적 파일을 보존했고, 금지된 Git 명령은 실행하지 않았다.

1. **벽에서 후퇴 방향이 고정되던 원인**

   기존 `ChooseRetreat`는 일반 후퇴를 플레이어와 거리를 벌리는 이동으로만 해석했다. 플레이어 쪽 후보를 제외하므로 오른쪽 벽에서 왼쪽으로, 왼쪽 벽에서 오른쪽으로 빠지는 이동도 선택할 수 없었다. 공간이 없으면 후퇴를 보류하는 처리는 있었지만, 반대 방향의 벽 탈출 상태가 없었다. 후퇴 실행 중에도 `dx * direction > 0.05`가 되면 종료하므로 방향 선택만 뒤집어서는 탈출이 시작 즉시 끝난다. 잔상 역시 플레이어를 바라보며 뒤로 이동할 때만 생성했다.

2. **좌우 벽 탈출 구현**

   일반 후퇴와 `swordWallEscaping` 재배치를 구분했다. 플레이어 반대 방향의 실제 이동 여유가 `min(6, 목표 거리×0.45)`보다 작으면 반대쪽을 검사한다. 반대 방향이 최소 `max(4, 막힌 방향 여유+2)`유닛 확보되고 탈출 재선택 제한이 끝났다면 그쪽으로 연속 슬라이딩한다. 현재 목표는 기존과 같은 16유닛이다.

   경기장 경계, BoxCast의 충돌 법선·거리, 장애물 Collider2D, 0.5유닛 간격 바닥 경로와 끝점을 검사한다. 실제 활성 충돌체가 있으면 그 bounds를 사용하고, 현재 보스처럼 충돌체가 없으면 기존 이동용 1.6×3.2유닛 가상 몸체를 사용한다. `KarmaSurface` 표시가 없는 일반 장애물 Collider2D도 막는다. 매 프레임의 충돌·바닥 검사도 유지했다.

   현재 게임은 보스 루트에 물리 Collider2D를 생성하지 않고, 별도 공격 판정과 지형 검사로 전투한다. 따라서 벽 탈출은 현재 허용된 비고체 보스 이동 규칙 안에서 플레이어 쪽으로 지나갈 수 있다. 충돌 무시 호출이나 무적 효과를 추가하지 않았다. 실제 고체 보스 충돌체를 추가한 검증에서는 플레이어와의 충돌 설정을 확인해 위험한 통과를 거부했다. 반대편도 막혔으면 후퇴 토큰을 보류하고 공격 기회로 전환한다.

   벽 탈출 재선택은 시작 후 5초 동안 제한하고, 종료 후 3초간 원래 벽 방향으로 돌아가는 후퇴를 억제한다. 일반 후퇴의 1.2초 쿨다운, 공격 완료 조건, 0.65초 공격 기회, 가감속은 유지했다. 탈출 중에는 플레이어 쪽 이동이라는 이유만으로 종료하지 않는다. 준비·충돌·이동 실패·거리·시간 종료 조건은 유지한다.

   잔상 컴포넌트에는 재배치 모드를 추가했다. 일반 후퇴는 기존 방식 그대로이며, 재배치 중에는 이동이 앞/뒤 어느 쪽이든 실제 지난 프레임의 외형을 지나온 월드 위치에 남긴다. 이동하지 않으면 잔상도 생성하지 않는다. 기존 청백색 이미지·재질·수명은 변경하지 않았다.

3. **벽 탈출 방향 및 반복 검증**

   | 시작 | 플레이어 위치 | 실제 탈출 | 반복 | 실측 거리 |
   |---|---|---:|---:|---:|
   | 왼쪽 벽 | 보스 오른쪽 | 오른쪽 | 50회 | 매회 15.99984유닛 |
   | 오른쪽 벽 | 보스 왼쪽 | 왼쪽 | 50회 | 매회 15.99984유닛 |

   Play Mode에서 실제 이동 코드와 Physics2D를 사용하고 60Hz tick으로 좌우 각각 50회 반복했다. 매회 43프레임, 약 0.717초에 완료했고 벽을 향한 역방향 이동은 없었다. 최고 속도 32유닛/초 제한과 새 플레이어 무적 없음, 종료 후 같은 벽으로 즉시 복귀하지 않음을 확인했다. 원시 데이터는 `wall-100.csv`다.

   별도의 정상 Update 검사에서는 양쪽 모두 청백색 잔상 최고 6개와 슬라이딩을 실제 렌더했고, 종료 뒤 정상 공격이 재개됐다. 일반 장애물로 반대 방향을 막은 경우와 실제 고체 보스 충돌체를 추가한 경우에는 탈출을 거부했다. 이 검사는 사람의 직접 입력이 아닌 자동 Play Mode 검사다.

4. **SW03 반복 횟수 변경**

   `SW03.cs`의 일반 3차례 / 강화 4차례 분기를 **양쪽 모두 고정 5차례**로 바꿨다. 차례마다 새 배치를 선정하고, 지면 전조→상승→소멸·간격을 거쳐 다음 차례로 진행한다. 차례당 10구간×2개=20개 생성, 높이 30, v5 이미지와 피격 효과, 안전 경로 planner는 변경하지 않았다.

5. **SW03 검기 개수·패턴 지속 시간**

   | 상태 | 차례당 검기 전→후 | 반복 전→후 | 전체 검기 전→후 | 실측 전체 시간 전→후 |
   |---|---:|---:|---:|---:|
   | 일반 | 20→20 | 3→5 | 60→100 | 6.200→9.900초 |
   | 강화 | 20→20 | 4→5 | 80→100 | 7.717→9.517초 |

   고정 60Hz, seed 6103, 일시정지·플레이어 스턴 없이 패턴 시작부터 회복을 마치고 `running=false`가 될 때까지 측정했다. 다음 패턴 선택 대기 시간은 제외했다. 변경 전 소스는 검증 복제본에만 적용하여 직접 재측정했다. 강화는 기존 Tempo의 경고·회복 단축이 유지되어 일반보다 약간 짧다.

   변경 후 각 차례 발사 시각은 일반 `0.867 / 2.717 / 4.567 / 6.417 / 8.267초`, 강화 `0.817 / 2.617 / 4.417 / 6.217 / 8.017초`였다. 매회 활성 검기는 정확히 20개이며 이전 차례와 과도하게 겹치지 않았다. 다섯 번째 종료 후 판정 정리와 정상 회복 완료를 확인했다.

   기존 검증을 5차례 기준으로 갱신해 일반 반복 피격 중에도 전 차례 완주, 전조·판정 위치 일치, 구간별 공유 접촉 기록, 기존 v5 이미지·실제 피해 시 피격 효과, 패링·스턴·사망 정리를 확인했다. 무적을 끈 실제 충돌 검사 이동으로 5차례 회피 검사도 통과했다. 변경하지 않은 planner의 순수 C# 회귀 검사도 56,872개 배치 / 2,261개 조합을 통과했다.

6. **SW04 실제 패링 성공 연결 위치**

   기존 실제 경로는 `KarmaBossAttack.Update → KarmaEnemy.TryAttackHit → KarmaPlayer.TakeDamage → techniques.ConsumeCounter`다. 플레이어의 `ParryCount`가 증가한 경우에만 성공으로 처리한다.

   `KarmaEnemy.Presentation.cs`의 기존 성공 분기에 **발사 원본이 SW04이고 동작 타입이 SwordBossBehavior인 경우만** 전달하는 세 줄과 주석을 추가했다. `SwordBossBehavior.CounterParried(contact)`가 해당 SW04의 접촉 기록으로 전달한다. 플레이어 코드·패링 판정·기존 패링 연출은 변경하지 않았다. 일반 충돌, 보스 피격, 가드와 혼동하지 않는다. 원본 패턴을 사용하므로 SW04가 다른 공격과 독립적으로 비행 중이어도 연결된다.

7. **1~4번 패링 결과와 제거 범위**

   | 실제 패링 성공 | 후속 제거·예약 취소 | 먼저 발사된 검기 |
   |---|---|---|
   | 1번 | 2·3·4번 | 없음 |
   | 2번 | 3·4번 | 1번 유지 |
   | 3번 | 4번 | 1·2번 유지 |
   | 4번 | 없음 | 1·2·3번 유지 |

   각 항목을 **후속 발사 대기**와 **이미 네 발이 비행 중인 제어 상황**으로 나누어 총 8개 사례를 실제 `BeginCounter → 공격 Update → ConsumeCounter` 경로로 독립 검증했다. 동시 비행 상황은 검증 복제본에서 탄속·수명을 일시 고정해 만들었다. 런타임 발사 속도·수명 설정을 바꾸지는 않았다.

   반격 묶음마다 증가하는 ID, 네 접촉 기록과 발사 순번, 순번별 소유 루트를 부여했다. 성공한 순번보다 뒤의 접촉 기록은 즉시 소비 처리하고, 루트를 동기적으로 비활성화한 후 삭제 예약한다. 해당 루트 아래의 투사체·경고·발사 섬광·잔상도 함께 비활성화된다. 같은 프레임에 후속 검기 Update가 남아 있어도 이미 소비된 접촉 기록으로 피해를 줄 수 없음을 직접 확인했다.

   추적·방향 고정·다음 발사 대기의 반복문과 발사 직전에도 허용 순번을 확인한다. 이미 생성된 후속탄뿐 아니라 아직 발사되지 않은 탄도 취소한다. 패링한 탄 자체는 기존 패링 처리를 따르며, 앞선 탄은 소급 삭제하지 않는다. 별도의 SWBasic 공격을 함께 놓고 영향을 받지 않는 것도 확인했다. 일반 피격과 가드는 취소를 일으키지 않고 정상 네 발 발사를 유지했다.

8. **SW04 정상 종료 및 재사용**

   패링 후 발사 예약을 끝내고 앞선 탄들의 원래 수명이 끝날 때까지 기다린 후, 기존 독립 반격 상태를 정리한다. `guardResponseRunning`이 해제되고 소유 루트와 묶음이 정리됨을 확인했다. 현재 본 패턴의 애니메이션·상태를 새로 강제 중단하지 않는다. 기존 SW04 투사체 패링이 보스를 무조건 스턴시키지 않는 규칙도 유지했다. 기존 강제 패링/스턴 경로는 그대로다.

   SW04를 다시 사용하면 새 ID와 접촉 기록 네 개가 생기며 정상 네 발을 발사했다. 이전 묶음 접촉 기록을 전달해도 새 묶음에는 영향이 없었다.
